# SoftwareEngineer technology normalization plan

## Goal

Replace the denormalized `SoftwareEngineer.techStack` string with a normalized many-to-many relationship between software engineers and reusable technologies.

The current values can contain comma-separated data such as:

```text
sql, databases, java, spring
```

This should become separate rows linked through a join table.

## Recommended data model

Use `Technology` as the entity name rather than `TechStack`, because the existing values represent individual technologies. A named stack such as `Java backend` could be introduced later as a separate concept.

```text
software_engineer
-----------------
id                 PK
name
aggregate_version

technology
----------
id                 PK
name               UNIQUE, normalized

software_engineer_technology
----------------------------
software_engineer_id         FK -> software_engineer.id
technology_id                FK -> technology.id
PRIMARY KEY (software_engineer_id, technology_id)
```

## Design decisions to confirm

- [ ] Confirm that an engineer can have multiple technologies.
- [ ] Confirm that technologies are shared and reusable across engineers.
- [ ] Confirm that technology names should be case-insensitive.
- [ ] Confirm whether `Java` and `java` must resolve to one row.
- [ ] Confirm whether technology display casing should be preserved separately from the normalized lookup value.
- [ ] Confirm whether technology ordering matters. Default assumption: no ordering, therefore use a `Set`.
- [ ] Confirm whether the API should expose technology names, IDs, or both. Recommended: names externally, IDs internally.
- [ ] Confirm whether an empty technology collection is valid. Recommended: reject empty collections for new and updated engineers unless the business requires otherwise.

### Suggested JPA relationship

```java
@ManyToMany
@JoinTable(
    name = "software_engineer_technology",
    joinColumns = @JoinColumn(name = "software_engineer_id"),
    inverseJoinColumns = @JoinColumn(name = "technology_id")
)
private Set<Technology> technologies = new HashSet<>();
```
